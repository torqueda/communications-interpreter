Letter Explainer (working title)

A small Python web server on your laptop serves one web page. Code numbers the letter's sentences before any AI sees them. A Reader agent translates and marks them, a Verifier agent checks the work, and plain code proves every point traces back to a real sentence.

How a letter moves through the system

Browser Plain code (deterministic) AI call (Gemini or Ollama)

Stack

  • Python 3.11+ with FastAPI and Uvicorn: the web server. New to you, and the subject of a separate walkthrough.
  • Pydantic: data models that double as the JSON schema each AI must follow.
  • Gemini by default (your $8.52 credit), or Ollama locally for free, text letters only.
  • PyMuPDF for PDF text and generated test letters. pytest for tests.
  • Plain HTML, CSS, and JS for the page, with no build step.

Not looked up yet: current Gemini model names and prices, the SDK's exact syntax, and which Ollama model handles Spanish well. These get verified at the start of the build.

Components

code

Web server

app/main.py

POST /api/explain takes the file and returns LetterResult or an error code. GET /api/config tells the page which file types the current mode accepts. It also serves static/.

Ingest and segment

ingest.py · segment.py

PDF text comes from PyMuPDF and TXT is read directly. Images pass straight through to the Reader in Gemini mode only. Empty text returns cannot_read. A rule-based splitter numbers the sentences, with unit tests for "a.m.", "Dr.", and phone numbers.

Providers

app/providers/

One function, generate_json(system, prompt, schema, image), with two implementations. Gemini supports images; Ollama is text only. PROVIDER in .env picks one. Each provider validates with Pydantic and retries once.

AI

Reader agent

agents/reader.py
  • Language check, and transcription for images
  • Spanish translation per sentence ID
  • A highlight kind per sentence
  • Bilingual summary items citing sentence IDs
  • Deadline date, needs-action flag, incomplete flag
  • Scam flag with reasons

Verifier agent

agents/verifier.py

A separate, skeptical call. Each item comes back ok, fixed (with a correction), or unverified, and it reviews the scam decision. If it disagrees, the warning still shows, with its note added as one more reason.

Code checks

checks.py · pipeline.py

Cited IDs must exist. Fixes get applied. Anything failing gets verified: false, which shows as "Couldn't verify, check the original." deadline_passed comes from comparing dates. The warnings list: past_deadline, incomplete, image_source.

The one screen

static/

i18n.js holds every interface string in Spanish and English. app.js handles the language picker, upload, animation, scam gate, matched highlights, tooltips, "Show in letter," caution boxes, disclosures, and Start over and Close. Only the language choice is saved, in localStorage.

Test letters and evals

test_letters/ · evals/

Each fabricated letter comes with an expected.json of properties. run_evals.py runs the real pipeline and prints a pass/fail table, which is your "more trial cases" goal. An Ollama subset covers the text letters.

Where data lives

The letter and its resultServer memory for one request, then the page's memory until Start over, Close, or closing the tab. Never saved.
The language choiceThe browser's localStorage. It survives a reload and contains no letter data.
API key and provider.env on your machine. It's gitignored and never sent to the browser.
Test lettersThe test_letters/ folder, all fabricated and committed to the repo.

Where it breaks, and what you see

Malformed JSON from the modelOne retry, then the "something went wrong" message with Try again.
A point cites a sentence that doesn't existShown with "Couldn't verify, check the original," never silently trusted.
Slow model (10–30 s)The animation keeps playing, with a timeout after about 90 s.
Scanned PDF with no textGemini reads it as an image and adds the image caution. Ollama returns "can't be read."

Decisions

Yours

  • FastAPI with plain JS, not React
  • Gemini by default, Ollama as a free text-only mode
  • Accept the screenshot risk, with a caution notice on image uploads
  • Local only, no deployment
  • You set up GitHub yourself, with guidance

Derived (for your review)

  • Code numbers sentences before any AI call
  • Two checking layers: the AI verifier for meaning, code for existence and dates
  • .txt uploads accepted; images turned away in Ollama mode
  • Language choice kept in localStorage

FastAPI walkthrough: a separate artifact built from your real code once the server exists. Claude features to try during the build: a hook that runs tests after edits, subagents that draft test letters in parallel, and /code-review before shipping.
